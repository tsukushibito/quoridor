# ユーザー追補: 強くなる設計・学習を目標にする

ユーザーの最新指示:「特徴に距離マップが含まれているのであれば、距離評価だけよりNNUEの方が強くならないとおかしい。というか、強くなるように特徴設計や学習環境を構築するべき。」

採用方針: 距離評価を超えるNNUEを作ることを明確な到達目標とする。主問いは貢献有無の採否ではなく、期待される利益がまだ出ない原因と必要な設計・学習改善。NNUE不支持で研究を畳む短絡や小smokeを最終性能とすることは避ける。理論的・自動的な強さ保証と実証を混同しない。

重要な現実確認: crates/quoridor-nnue/src/features.rs の現行QF1は二視点312疎入力＋distance[2]（両駒の壁のみ最短距離/80、STM順）。distance_mapは内部で各81マスを計算/cacheするがNN入力へ渡すのは駒位置の2値。全距離マップ入力済みではない。docs/design/ai-nnue-feature-design.md のQF1と到達T1案も区別する。

最初の選定に、距離baselineが実際に使う値/非線形変換/残壁/contextとNNUEの入力/出力/探索接続の対応を含める。距離関数を再現する情報と表現が足りるか、現教師とlossがその基準以上へ学習を誘導するかを低費用で確認する。盤面情報があるだけで小モデル・有限教師が経路計算を自然に再学習したとはしない。距離baselineを保持できる設計（直接距離項＋残差等）や経路特徴拡張も競合案として費/一般化/棋力で選び、前の小残差不支持を全設計の否定にしない。全距離map/T1追加を無条件一斉実装せず、現在不足を最も判別し改善する案へ配分する。
