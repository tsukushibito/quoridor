# Quoridor NNUEの特徴設計案

2026-10-03、quoridor-4lc.189。ユーザーの「NNUE型で最強のQuoridor AI」を目指す具体設計。上位方針は[NNUE研究方針](ai-nnue-research.md)、目標は[研究目標](ai-sigma-research-goal.md)。本書は実装・比較に使う仮説であり、最強になる特徴や採用済みモデルを断定するものではない。実行配分は現在の研究枠内でチームが判断する。

## 現時点の到達構成：QF-T1

**完成形の本命は「二視点NNUE＋壁の局所連結＋少数の経路・移動特徴＋選択的な方策出力＋αβ/PVS」とする。** 下記QF1はこの構成へ到達するための小さい比較基準で、QF-T1が現在選ぶ到達案。候補の列挙だけで終えず、次の構成を中心に実装・学習・棋力の費用対効果を確かめる。幅や計算頻度は未実測の設計値であり、最強・最適を認定した数値ではない。

### 516の壁ペアと更新量

盤の境界格子を0…9の座標で表す。`a=8*y+x` のH壁は線分 `(x,y+1)–(x+2,y+1)`、V壁は `(x+1,y)–(x+1,y+2)`。128壁候補の異なるunordered pairから、同方向なら端同士が接し、異方向なら少なくとも一方の端で接するものを選ぶ。重なり・中央同士の交差は除く。これで **516組**となり、一つの壁が関係する組は最大10。各組を `(壁ID小, 壁ID大)` の辞書順で312…827へ割り当て、両壁が置かれたときだけ有効にする。壁IDはHが0…63、Vが64…127。各固定視点へ回転してから同じ一覧を用いる。

これは一直線の連結、角、T字の接触を表す。盤端への接触は壁位置から既に決まるので、同じ情報の線形な複製は追加しない。pairは局所関係であり、盤全体の包囲・通路の安全性は経路特徴と学習に任せる。

壁手の更新は各視点で基本3vector＋成立したpair最大10、**最大13vector**。pawn手はpairが変わらず2vector。有効特徴数の保守的上界は基本24＋`20壁×10/2`＝124とし、QF1の24を量子化overflow計算へ流用しない。共有transformerは211,968重み、int16で423,936B（414KiB）。二視点で重みを二重保持せず、後段・accumulator stack・距離cacheの費用を別に測る。

516組・最大10・次元算術は幾何線分とanchor差の二通りで列挙照合し、180度回転・左右鏡映で集合が閉じることを確認した。全pairが任意の局面で合法に置けるという意味ではない。実局面の合法性はルール実装が決める。

### 後段へ入れる16＋4値

次の8値を各側について求め、手番側・相手側の順で16値にする。wall-only map `D_p` の意味は第3節と同じ。

| 各側の8値 | 定義・正規化 |
| --- | --- |
| 現在の最短距離 | `D_p[pawn_p]/80` |
| 次の駒手を含めた距離 | `1+min D_p[q]` を81で正規化。qはjumpを含む、その側が今動けると仮定した幾何的な合法駒移動先 |
| 最短方向の数 | 壁だけの隣接辺で距離が1減る方向の数、最大4で正規化 |
| 駒の移動先の数 | 同じ幾何的合法移動先の数、標準2人ルールの最大5で正規化 |
| 直線jumpの有無 | 0/1 |
| 斜め回避の有無 | 0/1 |
| 最短経路の選択肢 | ゴールを1、他を距離が1減る隣接先の和とするDPの件数C。255で上限を付け、`log(1+C)/log(256)` |
| 最短経路の到達ゴール数 | 同じ最短経路DAGで到達するゴール升の9bit集合をORで求め、popcount/9 |

`D,C,ゴール集合` は壁配置とゴールにだけ依存し、距離順DPを一緒に計算してpawn手では参照位置だけ変える。jump・移動先の値は両pawnに依存する安い局所計算。合法な非終局状態では現在pawnとその幾何的移動先からのwall-only距離は有限、移動先集合は非空として検査する。map内の不可達升や不正入力を通常の距離へclipしない。最短経路の件数・到達点が多くても途中で同じ狭い箇所へ合流し得るため、独立経路数や壁に対する耐性とは呼ばない。

context4値は、規則で正規化した残りply、ply上限の有効flag、規則で正規化した現在局面の反復回数、反復規則の有効flag。規則がなければ値とflagを0にする。これで履歴全体を表現したことにはならず、正確な終局・反復判定は探索側に保持する。文脈やルール版が異なるNN/TT結果を無条件に共有しない。

### 方策・探索・学習まで含めた完成形

方策136は「駒の8方向＋H64＋V64」。直線jumpは同方向の通常移動と同時に合法にならないため同じ方向枠に対応付ける。斜めは別4方向。実際の方向順、P2変換、Sigma教師の既存順からの変換をfeature/model版に定義し、製品の移動先Action IDへ写像する。違法手をmaskし、順序付けではsoftmaxを省略できる。

TT手と正確な即勝ち手を優先し、残りを方策と履歴で並べる。根では方策上位8壁の両者への正確な距離変化を追加計算して、安い方策が見落とす妨害効果を順序へ補う案を選ぶ。子の距離結果は再利用する。これは全128壁の効果を全葉で計算する構成ではなく、上位以外の合法手も探索対象に残す。計算頻度・上位数の利益がなければ削る。LMR等の選択的探索はこの基準の後に対局で判断し、方策が小さいという理由だけで手を捨てない。

価値は手番側の期待得点を表し、drawは0.5とする。到達案ではscalar logitから `p=sigmoid(s)` を学習し、探索では順序を保つscale済み整数logitを使える。pをdraw抜きの勝率と呼ばず、終局の確定値を別にする。rootmean由来の期待得点・正当な終局z由来の得点は別のvalid maskと係数を持つ教師として扱う。小試作QF1のMSEとは別条件とし、lossを無言で置換しない。

価値を主目的、方策を補助目的として同時学習する。係数は実験に固定し、数値scaleが大きいπ lossに引っ張られてvalueの符号・校正を悪化させない。game/familyごとの重み付けで長局の行数だけが学習を支配することを避ける。最初は既MCTS教師から蒸留し、強い探索による再ラベルと自分のαβ局面・終局結果を加えて、教師分布への依存を減らす。学習済みQF1の重みを異なる形のT1へそのまま読み込まず、必要なら明示した新モデルへ再学習・蒸留する。

H256・後段32・残深さ3・根8壁は現時点の具体的な到達設定。全要素を一度に導入して一因子の利益と主張せず、**まずQF1でαβに接続し、T1へ進める中で同時間棋力に寄与しない部分を削る**。既48局だけでT1を十分に学習できるとは見込まない。大量教師を用意する間も小試作を進め、完成形の全実装やPVのSigma同等認定を現在の研究の入口にしない。

## 推奨する出発点：QF1

**盤面の疎な特徴を二視点で差分更新し、壁だけのグラフから得る両者の最短距離を小さな後段へ加える。** 最初は価値評価のみでαβへ接続する。駒と壁の局所関係・経路の選択肢・方策による手の順序付けは、実測された弱点に応じて追加する。

狙いは、壁配置の意味を学べる情報量と、探索内で頻繁に評価できる費用を両立させること。入力数・教師との一致・nodes/secの一つだけで採用せず、特徴生成から探索までの実費と同時間棋力を判断材料にする。自前PVモデルの完成をNNUEの小試作の入口にしない。

## 1. 盤面・視点・入力の意味

標準9×9・各10枚の壁を出発点とする。駒の升は `s=9*y+x`、壁のanchorは `a=8*y+x`、H/Vは壁の向き。基準実装のP1はrow 8、P2はrow 0を目指す。壁には配置した人の所有属性を付けず、各プレイヤーの残り壁数を別に入力する。

推奨版 `QF1` は**各固定プレイヤー視点312次元**。手番は両視点の結合順と後段で表す。過去156の「固定座標313＝312＋手番bit」とは別のfeature versionにし、旧学習済み重みを読み替えない。

| index | 特徴 | 次元 | 1局面で有効な数 |
| --- | --- | ---: | ---: |
| 0–80 | 自分の駒が升sにある | 81 | 1 |
| 81–161 | 相手の駒が升sにある | 81 | 1 |
| 162–225 | H壁がanchor aにある | 64 | H壁数 |
| 226–289 | V壁がanchor aにある | 64 | V壁数 |
| 290–300 | 自分の残り壁数が0…10 | 11 | 1 |
| 301–311 | 相手の残り壁数が0…10 | 11 | 1 |
| 合計 | 二値入力。残り壁0も有効なone-hot | **312** | **配置壁数＋4、最大24** |

P1視点はそのまま、P2視点は180度回転して所属を交換する。駒は `s→80-s`、壁anchorは `a→63-a`、壁のH/Vは変わらない。各視点の自分のゴールはrow 8になる。固定Sigma入力の上下反転とは別変換なので、既648入力を黙って流用しない。

二つのaccumulator `A_P1, A_P2` を常時保持し、同じ重みを共有する。各視点はプレイヤーに固定し、手番交代で入力全体を作り直さない。後段には `A_手番側, A_相手側` の順で渡す。左右鏡映は学習拡張候補で、棋譜・壁・方策・履歴を一緒に変換し同じデータ分割へ所属させる。

「プレイヤーとゴールを入れ替えて盤面を回転した同等局面」と「同じ盤面で手番だけ変えた局面」は区別する。後者には手番の価値があり、評価が必ず符号反転すると強制しない。

## 2. 差分更新とネットワーク

各視点で `A_p = b + Σ W[有効feature index]` を保持する。駒移動は旧升を引き新升を足す。壁配置は壁1特徴を足し、その側の残り壁one-hotを交換する。**1視点あたり駒手2vector、壁手3vector**の更新が基本で、両視点を更新する。手番交代は後段の結合順を変える。非合法手・終局処理はルール側が扱う。

make/unmakeでは親のaccumulatorと距離map参照を探索stackへ保存・復帰する方法から始める。親と子で可変bufferを共有して親を壊さない。全再計算版と差分版が一致することを、通常移動・jump・斜め回避・H/V壁・P2・復帰で確認する。疎特徴の一致だけで、後段の距離や履歴まで一致したとしない。

最初のモデル案は `312→H` の共有feature transformerを二視点に用い、`concat(2H, 経路, 必要context)→32→value`。H=128から小さく試し、容量不足が示された場合に256等と比較する。これはQF1の初期形で、到達案T1の層構成とは区別する。推奨初期値であって全幅の総当たりはしない。H=128の共有transformerは39,936重み、int16重みだけなら約78KiB。これは全モデル・探索stack・距離cacheのRAMではない。疎な入力でも後段は通常毎評価で計算する。

量子化はfloat版の学習と動作確認から接続し、整数向けactivation・scale・丸め・accumulator幅を版へ含める。最大有効数24と各重み範囲からoverflowを検査する。floatとの差分誤差に加え、評価順位・探索・棋力を確認する。最初のfloat試作だけでNNUE本来のCPU速度を認定しない。

モデル出力にはfeature version、座標変換、層の形、activation、重み・biasの型とscale、valueの視点・変換を含める。ONNXは学習側との全再計算parityに利用できるが、探索内の差分評価にはaccumulatorを扱うnative評価器と専用重み読込が必要になる。探索stackの保持量は深さとHで見積もり、全TT entryへ無条件にaccumulatorを複製しない。

## 3. 経路情報は計算範囲ごとに分ける

### 最初に加える2値

壁だけの無向グラフを `G(W)` とし、プレイヤーpのゴール列から逆向きmulti-source BFSで `D_p[s]` を求める。駒を障害とせず、`d_p=D_p[pawn_p]` を得る。後段へ手番側・相手側の2距離を渡す。通常の有限距離0…80は例えば80で正規化し、不可達を0・距離80・勝敗へ混ぜない。配置壁が合法でも空き升の一部がゴールから孤立する可能性があるため、mapの不可達表現は保持する。

この距離は将来の壁・相手の移動・jumpを含む実際の勝利手数ではない。距離差だけに圧縮せず、まず両方の距離を渡して終盤と中盤を区別できるようにする。残り壁one-hotと組み合わせ、同じ距離差でも残り壁の非対称性を学習できる構成にする。

### 有力な追加候補

| 候補 | 意味と期待する効果 | 更新・計算費と落とし穴 |
| --- | --- | --- |
| 直近の移動による到達改善 | 各側の合法な駒移動先qから `1+min D_p[q]`、即ゴール手の有無など。jump・接触・斜め回避を補う | 実ルールの駒移動生成を再利用。相手側の値は「今手番なら」の幾何的候補と明記。相手が動く将来の厳密距離とは呼ばない |
| 最短方向の選択肢 | `D_p[n]=D_p[s]-1` となる通行可能な隣接辺数。一本の通路への依存を補う | mapから局所参照できるが、独立した経路本数・壁への耐性とは同一でない |
| 最短経路上の分岐・合流 | 距離が1減る辺だけのDAG上で経路の共有区間や迂回可能性を表す | pawn位置が変わると対象経路も変わる。単なる最短経路数は大量に重複した経路を過大評価し得る |
| 安全な局所移動数・相手との接触 | 狭い通路、対面、壁際での行動制約を補う | wall-only mapとは異なり両pawnに依存。合法手生成との二重計算を避ける |
| 合法壁による距離増加 `Δd` | 相手への妨害、自分への副作用、壁1枚の価値を表す | 高価な一手先計算。まず根・浅い探索・方策による順序付けの候補に限定して利益を測る |

最初から全候補を入力しない。距離を加えても残る誤りの種類から、一つの特徴群を選ぶ。学習される有効性は仮説であり、幾何情報が計算上正確なことと最善戦略を表すことは別である。

### mapの再利用と壁の影響

`D_P1,D_P2` のcacheは壁配置・盤サイズ・ゴール・ルール版に対応付ける。駒位置・手番・残り壁数には依存しない。壁不変の駒移動はmapを共有して位置参照だけを変える。壁を置いた子では新mapを計算するか、別途検証した更新法を用いる。hash衝突確認と容量上限を持ち、親が使用中のmapを破壊しない。最初はstack上の共有参照で十分かを測り、大規模な汎用cacheを前提にしない。

**壁だけのmap cacheと、合法壁cache・NN評価cache・置換表は異なる。** 合法壁には両pawnの到達可能性、実際に打てる壁には残り壁、評価にはpawn・手番・モデル/feature版、探索boundには深さ・履歴等が関係する。wall hashだけで全てを共用しない。

追加候補壁が、あるpawnについて保存した有効な最短経路の辺を一本も切らない場合、そのpawnのwall-only最短距離は増えない。元の最短経路が残り、辺の削除で短くもならないためである。これは当該pawnの距離に限る。交差・重なり・もう一方の到達可能性を省略できず、全81升のmapが不変とも言えない。経路を切る場合は距離増加の可能性だけが分かり、別の最短経路が残ることもある。

全128壁候補ごとに2回BFSする方式は高価な対照として扱う。最良の壁を読む必要がある局面だけの計算、経路に影響しない候補の厳密な除外、bitboard floodなどを必要に応じて比較する。両者が壁を使い切ってもpawnの接触・jumpがあるため、距離差だけで勝敗を厳密判定しない。

## 4. 駒と壁の関係をどう学ばせるか

基本の疎特徴は盤面を表せるが、浅いネットで長い迂回や囲いを十分に学べるとは限らない。QF1から比較する拡張候補は次の三つ。到達案T1ではこのうち壁ペアと後段の経路・移動情報を選び、pawn位置×全壁などは追加比較候補に留める。

1. **小さな局所関係**：各pawn周囲の通路・壁の配置、相手との相対位置。関係が重要な範囲だけを符号化し、pawn移動で再計算する特徴数を小さく保つ。遠い壁の影響は基本壁特徴と距離で補う。局所半径は実測で選び、局所情報だけへ置換しない。
2. **壁同士の局所連結**：隣接・近接する壁や盤端との接続で囲い・通路を表す。壁配置時だけ変わるため、pawn移動の差分には乗らない。全128×128組を無条件に導入せず、関係する配置組へ絞る。
3. **距離・壁残数の関係**：距離差と絶対距離、両者の残り壁の組み合わせを小さな後段や埋め込みで扱う。少ない教師で学べるか、bucket境界や距離clippingで重要な局面を同一化しないかを見る。

HalfKPの単純移植に相当する「各pawn位置×全壁位置」は、位置ごとの壁の意味を直接学べる強い対照候補である。一方、pawnが動くたびにそのpawnに結び付く配置壁の全組を引き直す。**コリドールでは主役のpawnが頻繁に動くので、玉移動時のrefreshを許容する将棋と同じ費用にはならない。** 自動却下はせず、得られる精度と追加更新・重み容量・学習量が見合う場合に比較する。

動くpawnを基準に盤面全体を平行移動する特徴、全距離map・全合法壁map・全候補壁効果を大きな差分層へ入れる特徴は、更新量が増えやすい。動的情報を小さな後段・方策側へ分ける案と比較する。

## 5. 履歴・終局・方策との接続

基礎312特徴は履歴を含まない。研究の反復回避やply上限が価値・合法手へ影響する場合、全履歴を含むルール状態は探索側に保持し、終局・反復・合法性をNNより先に判定する。必要なら残りplyや現在局面の反復回数を小さな後段へ加える。ただしその数値だけで全履歴依存を完全に表せたとしない。teacher行・NN cache・TTは、それぞれ実際に必要なcontextと版を区別する。

valueは「手番側から見た勝敗期待」を出発点とする。真の終局勝敗はNN出力より優先し、αβ用の整数scaleと勝敗確定値を定義する。局面を進めた時の符号反転、P2変換、先後交換、drawと未完了を揃える。勝敗に近い出力の飽和だけで正確な評価とは判断しない。

初期QF1はvalueのみとし、到達案T1では小policy headを選択的に計算する。軽量な候補手採点器も比較候補となる。TT手・履歴・距離による順序付けと併用し、壁手の特徴には候補anchor、向き、局所形状、必要時の両者のΔdを使える。候補全件の高価な特徴生成を毎葉で行うと利益を失うため、根・浅い局面等での限定計算を選ぶ。最初は順序付けだけに用い、方策による手の除外・深さ変更は効果を別に確認する。

既Sigma教師のπ136と製品Rustの209 Action IDは同じ配列ではない。policyを使う際は局面ごとに移動先・jump/斜め・H/V anchorを対応付ける。P2・対称変換も含めて保存された実手と合法massを確認し、単なるindex一致を教師対応としない。

## 6. 既教師をNNUEへ接続する

盤面・手番・残り壁・必要な履歴からQF1を再生成し、入力だけを独立検証できるようにする。既648入力しかない行について、消えた履歴やraw状態を推測して補わない。NNUE重みは新規学習し、Sigma重みや既小PV checkpointの直接移植はしない。

最初は、同じgame splitで**探索rootmeanを教師にする小さなvalue蒸留**を主候補とし、真の終局zへの誤差・符号・校正も別に評価する。rootmeanが欠測・不適格ならその教師には用いない。これはαβの厳密minimax値ではなく、教師model・MCTS規則・K・局面分布に依存する。K64の値は低予算の探索教師であり、高精度の正解とみなさない。

最小学習では手番側の連続値 `v∈[-1,1]` を出力し、適格rootmeanへのMSEを一つの基準にする。MSEを使うだけでvalueが勝率として校正されるわけではない。終局z・対局単位の符号誤り・飽和率を併記し、特徴比較では同じ教師/分割/学習費をできる範囲で揃える。教師の高K化・zとの混合・ネット幅変更を同時に動かして、特徴単独の効果と呼ばない。

root NN値・探索rootmean・終局zを別列に残す。混合target又は複数lossを試す場合は混合係数とvalid maskを実験条件に含め、無言で平均しない。zは完了した正当な対局のみ、fault/打切りをdrawや敗北に変換しない。policyを追加する場合の教師はroot訪問分布で、valueを流用しない。

序盤だけでなく、壁の多い迂回、残り壁の非対称、接触/jump、壁なし終盤、反復に近い局面を確認できる分布を作る。必要なら少数の重要局面を高Kで再ラベルする案と、局面数を増やす案を教師費用と学習効果で選ぶ。αβ試作後はその探索が訪れる局面も独立lineageで収集し、MCTS教師分布への依存を減らす。

分割はgame/family・色交換・対称変換単位で行い、同一状態の横断混入を点検する。履歴だけが異なる行を一律に重複削除しない。既48局は接続試作の材料であり、大きな特徴集合の優劣や最強の根拠には小さい。検証データで多数の設計を選んだ後の棋力認定には独立データを使う。旧173正式198局は学習へ転用しない。

## 7. 最短の比較経路と採否

すべてを実装する計画ではなく、次の選択肢から問いを一つずつ小さく判別する。

| 比較 | 分かること | 次の判断 |
| --- | --- | --- |
| QF0: 二視点疎盤面のみ → QF1: 距離2値追加 | ドメイン知識でNNUEのvalueを改善できるか | 距離計算込みの利益があれば基本案へ。費用が支配的なら共有/生成経路を改善 |
| 全再計算 → 同一重みの差分・整数版 | 正確さを保ってCPU評価を速くできるか | 数値対応と総探索費で採否。特徴の精度改善とは別に扱う |
| QF1 → 局所駒壁・局所壁連結・小経路特徴のいずれか一群 | どの戦略情報が不足しているか | game別/局面群別誤差と同時間棋力が改善する案を残す |
| valueのみ → 小policyで順序付け | 追加評価費より探索削減の利益が大きいか | 同じvalue/探索条件を基準に、強さと総費で判断 |

最初に特徴全体の大探索をせず、既教師から小valueモデルを学習し、最低限のαβへ接続する到達点を置く。低lossだけの最適化を続けない。小データで識別できない場合は、その限界を理由に教師分布・量を増やすか、強さ比較へ進むかをチームが判断する。

必要な整合確認は、full/delta/undo、視点と符号、壁変更後map、jump/斜め、不可達、terminal、履歴、量子化の範囲。既ルールfixtureを再利用し、新しい承認層や全履歴監査を入口にしない。

費用はcold/warm、pawn手/wall手、壁配置cacheのhit/missを区別し、特徴生成・合法手/距離・accumulator・後段・探索全体を測る。全壁候補の展開、履歴再生、重複map計算が主費用なら先にそこを直す。固定node/depth比較は機構診断、最終採否は同資源・同時間の対局で判断する。思考時間・相手・局面分布・版・不確かさを示し、「最強」は定義した比較範囲での結果として扱う。
