# SigmaQuoridor水準へ向けた自律研究の目標契約

契約版: 2。開始指示日: 2026-10-01（日本時間）。目標Beads issue: `quoridor-4lc`。
ユーザー指示: 「最初の目標はSigmaQuoridorと同等の強さ」「他のAIは参考として比較」「目標に向かった作業するようにチームに指示出して動かして」。

## 目標と判定

固定したSigmaQuoridorと同じ計算資源・思考時間で同等水準（上回る場合を含む）の強さを持つRust/Wasm AIを実装・検証する。ほかのAIへの対戦は参考比較。製品要件は[AI設計](quoridor-3d-webapp-design-rust-wasm-v1.md)、研究運用は[チーム設計](ai-research-team.md)に従う。

統括と検証担当が、参照commit/release・モデルハッシュ・特徴と行動encoding・探索/solver設定・開始局面・規約・先後入替・資源/持ち時間・非劣性許容差と信頼水準を結果を見る前に定義する。Sigmaの一部機能を落とした比較や探索を弱めた比較は条件を明示し、選んだ参照設定に対する結論として扱う。通常の比較条件決定は統括へ委任する。

初期の主比較は同一PC・CPU単一スレッド・GPU推論なし。同じ持ち時間で評価し、native/ローカルと製品ブラウザの両方を実測する。GPUや追加スレッドの研究結果は別条件にする。nativeの成績だけでブラウザでの到達を認定しない。持ち時間は機材と実装の計測から統括・検証担当が決めて固定し、従来の1手1秒案に拘束されない。

合法手、value視点、推論変換、キャンセル、応答性、メモリ上限、モデルの出所・配布条件を検証する。統括が独立検証の根拠を受け入れ、目標の達成を判定して目標issueをcloseする。目標未達や予算終了は達成扱いにしない。

## 担当と自律権限

統括: `coordinator` / `01a0f31b-3409-75f2-a30e-453a50484f94`。統括が目標issueをclaimし、課題定義、Beads子issueの登録・優先付け・担当分け、実験契約、採否、次の課題の起動を担当する。

今回のユーザー指示は研究実行の開始指示であり、以前の「準備試験のみ・研究未開始」の契約に代わる。目標の範囲内の調査、コード実装、対戦・性能計測、独立検証、必要なローカル依存の用意、固定参照コード/モデルの取得、小規模自己対局と学習は通常判断として委任する。毎回ユーザーの承認を求めず、競合仮説から安価な判別実験を選んで継続する。

まず現在のコードと比較可能性を確認し、仮説担当と基盤担当を並行して動かす。検証担当による評価条件の確認と、実験担当による最小計測・試作へ進める。統括は課題の選択を固定した逐次工程にせず、途中結果から分岐・中止・追加検証する。報告を受けたら、達成・停止条件に達していない限り次の課題を実際に依頼する。調査報告だけで全体を完了にしない。

五役の既存セッションを使用する。追加のサブエージェントはこの初期実行枠では使用しない。LLMの同時実行は統括を含めて最大3役。モデル・effortは現在のホスト設定を維持する。

## 作業場所と所有権

研究worktree: `/workspaces/quoridor/.worktree/ai-sigma`、ブランチ `codex/ai-sigma`。起点は主checkoutのHEADとし、最新のチーム指示・設計・操作入口を移入する。移入した未コミット内容も基準入力としてhashを記録する。

統括は研究契約・設計判断・受入れ報告を、実験担当は許可されたAI/ルール/bridge/評価・学習ツールを、ほかの役は指定した個別報告を所有する。一つの編集範囲の同時担当は一人。追加worktreeが必要なら、主checkoutを作業ディレクトリにして `scripts/dev/manage_worktree.sh` で作成し、基準差分を明示して渡す。

主checkoutと他worktreeの既存未コミット変更、UI・描画・VXGIの作業を保持する。既存のM2製品issue `quoridor-g89` は、この研究専用epicとは分けてdeferredを維持する。描画/UI作業を再開する必要はない。研究の採用変更は研究worktreeへまとめ、主checkoutへの製品統合・commit/push・外部公開は今回の実行枠に含めない。

契約と小さな検証報告はworktreeの `docs/design/`・`docs/reports/` に保存し、生データ・ログは `.artifacts/ai-sigma/` に保存する。実験/比較モデルはGit対象外の `models/experiments/`、一般依存と環境はinference cacheへ置く。[storage policy](../../.devcontainer/storage-policy.md)を守る。

## 初期の実行枠

2026-10-01（日本時間）のユーザー指示で、初期枠の終了を10:17:58から13:00へ延長した。変更は終了時刻のみで、以下の資源・学習上限および各実験の事前登録条件は維持する。

以下は今回の起動で設定する初期上限。統括が開始時刻と使用量・残量をBeadsと実行記録へ残し、上限内で実験へ配分する。

- 継続時間: 2026-10-01 13:00:00（日本時間） / 2026-10-01 04:00:00 UTCまで、または目標達成・ユーザーpauseまで。開始時刻は変更しない。各プロセスを残り時間以内のtimeoutで実行する。
- CPU: チームの計算ジョブ全体で最大4論理CPU。正式なCPU棋力/速度比較は1スレッド、他の重いチームジョブを止めて測る。並行する調査は可能。
- RAM: チームの実験プロセス合計8GiB以内。GPUを使う小規模実験は1ジョブ、VRAM 6GiB以内。既存の他者プロセスを終了しない。
- 小規模学習/生成: 検証できた特徴・棋譜・value・復元手順と計測根拠がある場合に実施。1ジョブ30分以内、学習GPU実行は累積2時間以内。大量自己対局・大規模学習は今回の枠に含めない。
- 新規の実験成果物・取得物・依存キャッシュは合計12GiB以内。開始時と大きな取得前に基盤担当が空き容量と対象を確認する。削除はこの研究が所有する再生成可能な一時物に限定し、失敗証拠・必要なcheckpoint・共有DBを保持する。
- Python依存は既存環境を読み取り利用するか研究専用環境へ用意する。共有学習環境の更新、システムtoolchain/Codex/App Serverの更新・再起動をしない。
- 現在のCodexホストとローカル機材を使う。追加の有料API・クラウド計算契約は行わず、第三者のオンライン対戦サービスへ自動対局を送信しない。

## 継続・報告・停止

依頼と報告は主checkoutの `scripts/dev/research-team.sh`、registryは `.artifacts/research-team/registry.json`。通信の `--issue` には継続中の目標issue `quoridor-4lc` を使い、本文に実際の子issueと契約参照を含める。各担当は子issueを確認・claimし、完了・handoff時に状態と根拠を更新する。送信前に目標と対象作業のpauseを確認する。

担当は書き込みを止めて統括へreportする。統括は受入れと次の依頼を行い、実行中の担当の報告待ちは担当とissueを明確にしてturnを終了できる。目標issueを個別実験の完了と同時にcloseしない。

実質的な改善、仮説の変更、目標達成、予算終了、進められない障害を統括チャットとBeads・報告に残す。通常の課題追加ごとにユーザーへ確認しない。足りない情報は調査と小規模計測で埋め、同じ条件の再試行だけを繰り返さない。

pause・異常終了・資源超過では関連プロセスのPID/ジョブIDと停止を確認し、ログ・checkpointを保存する。契約外の資源や大規模学習が必要なら、実測した根拠と具体的な追加案を提示する。
