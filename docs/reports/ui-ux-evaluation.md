# WebアプリのUI/UX評価（タイトル画面導入前）

評価日: 2026-09-30。Beads: `quoridor-1su`。
対象: 主checkout `2b24675`、通常production `http://127.0.0.1:4173/`。
既存の[HUD改善報告](ui-ux-improvement.md)と[描画改善報告](tabletop-rendering.md)を踏まえ、現在の表示と操作を再確認した。アプリ実装は変更していない。

本書は `2b24675` 時点の調査記録であり、以下の「現在」「今」は評価時の状態を指す。後続の改善 `4175e01` で、タイトル画面と共通の遊び方、やり直し確認、AI思考量の名称、再開を優先する保存案内を実装した。最新の動作と検証結果は[タイトル・遊び方・PC操作の改善報告](title-help-implementation.md)を参照する。スマートフォン向けの改善は今回の実装対象外とし、当時の観察結果をここに残す。

## 総評

木製盤、駒、テーブル、室内背景のまとまりは良く、PCでは盤面を中心に遊べる構成になっている。
基本操作と保存復帰も成立しており、ルールを知っている人がPCで対局する用途には使える。
一方で、初めて遊ぶ人への説明とスマホの操作案内が不足している。
今の改善優先度は、初回案内、タッチ時の表示、進行を失う操作への対処が高い。

これは画面観察と実ブラウザ操作に基づく評価であり、人間のユーザーテストやM1全体の最終受入れを代替しない。

## 良い点

- **盤面に集中できる。** 全面3Dと独立したHUDで盤上の操作領域を確保している。PCの初期画面では移動先のリングも見つけやすい。
- **視覚表現が統一されている。** 木材、駒の塗装、接触部の影、背景のぼけが卓上ゲームの雰囲気を作っている。暗い青の操作パネルと暖色の選択表示にも一貫性がある。
- **主要操作の名称が分かりやすい。** 「駒を動かす」「壁を置く」「1手戻す」から行動を選べる。手番と残壁は同じ場所で確認でき、駒の識別に色と形の表現を併用している。
- **対局条件の変更が明示的。** 新しい対局の設定を変えても、開始するまで現在の盤は変わらない。キャンセルと開始が分かれ、Escapeで閉じると入口ボタンへフォーカスが戻る。
- **着手前の反応と回復経路がある。** PCの壁hoverで配置プレビューと可否の文言が出る。タッチは候補選択後に確定できる。取り消しと保存からの再開も実操作で確認できた。

## 改善点と優先度

P1は、初回の理解や日常の操作に直接影響する改善。P2は、その後の分かりやすさや利用範囲を広げる改善。以下は評価上の優先度であり、改善実装を着手・承認した記録ではない。

| 優先度 | 観察した問題 | 利用者への影響 | 推奨する改善 |
| --- | --- | --- | --- |
| P1 | 初回表示にゲームの目的、ゴール方向、壁の基本制約を説明する入口がない。設定内にも入力方法だけがある | 移動できても何を目指すゲームか、壁をどう使うかが分からない。ルールを知っている前提が強い | 初回に短いルール案内を出し、後から「遊び方」で見返せるようにする。各駒のゴール側も示す |
| P1 | タッチ画面にも「クリック」「Enter」「Rキー」の案内が出る。駒移動の確定も「この場所に置く」。候補選択で下部HUDが2段になると案内文に重なる | タップ→確認の手順を説明できていない。操作に必要なタイミングで可否の文言が隠れ、駒と壁の操作も区別しにくい | タッチ向けの文言に切り替え、駒は「ここへ移動」、壁は「ここに壁を置く」にする。状態説明はHUD内の専用位置など、確定ボタン追加でも隠れない場所に置く |
| P1 | スマホ縦持ちの補助説明は9px、主要操作の文字は10px、ボタン高38px。横持ちでは盤が中央に小さく収まり、新規対局の開始ボタンは最初の表示範囲より下にある | 小さな文字を読む負担があり、横持ちではマスや壁候補の視覚的な識別が難しくなる。開始にはdialogのスクロールが必要 | 文字とタップ領域を拡大し、縦持ち・横持ちそれぞれでHUDを圧縮する。横持ちは盤の占有面積を増やし、dialogの開始操作を見つけやすくする |
| P1 | 対局途中に「やり直す」を押すと確認なしで0手へ戻り、保存も0手の履歴になる。「1手戻す」は無効になる | 誤って押すと進行中の盤と保存の両方を失い、戻す経路がない | 進行がある場合だけ確認を挟むか、直前の対局を復元できる取り消しを用意する |
| P2 | AIの思考量が48 / 96 / 192 / 4096（長考）だけで、時間や強さの違いが説明されない | 自分に合う選択ができない。数字が棋力や待ち時間とどう関係するかも分からない | 「速い」「標準」「じっくり」など選択の意図を示す。強さや秒数の表示は実測後に付ける |
| P2 | 保存あり起動時は「保存を破棄して開始」が暖色の強調、再開は通常色。設定内には「今すぐ保存」もあるが自動保存の仕組みは説明されない | 再開より破棄へ視線を誘導する。保存操作が必須なのか、自動保存なのか判断しづらい | 再開を主操作として強調し、「着手ごとにこのブラウザへ自動保存・1対局分」など保存の範囲を短く説明する |
| P2 | キーボード入力はあるが、候補の座標・駒と壁の配置は読み上げ用の情報として提供されない。可否の文言も「ここ」だけ | 盤を視覚で追えない利用者は局面や選択場所を把握できない | 候補の行列、駒位置、壁位置をテキストで確認できる経路と選択時の読み上げを設ける |

壁のマウス入力は、細い溝そのものだけに当てる実装ではなく、盤上の位置から近いアンカーを選ぶ。
したがって、今回の確認では「壁のクリック判定が細すぎる」とは結論しない。
密集した中盤での誤選択率や、実機で指に隠れる問題は別途ユーザーテストが必要。

## 確認範囲と結果

Chromium headless / SwiftShader / WebGL2で通常productionを操作した。
独立したブラウザcontextを使用し、ユーザーのブラウザ保存には触れていない。テスト用のアプリglobalは存在しなかった。

| 確認 | 結果 |
| --- | --- |
| PC 1440×900、タッチ縦390×844、タッチ横844×390 | 初期画面、壁モード、設定、新規AI設定を撮影。ページ自体の縦横スクロールなし |
| PCで駒移動→壁hover→壁配置 | 通常UIのマウス入力で0→1→2手。hoverの可否表示を確認 |
| PCでundoとやり直し | 2→1手へundo。やり直しで0手、保存のactionsも空、undo無効、確認dialogなし |
| 新規AI対局とAI応答、undo | 通常UIで人間が先手のAI対局を開始。人間とAIの着手後2手、undoで人間の意思決定前の0手へ戻る |
| 保存あり再読込→再開 | PCは1手、タッチは2手の局面へ復帰 |
| タッチで駒と壁を選択・確定 | 選択だけでは手数不変。確定ボタンでそれぞれ進行。候補選択時の案内とHUDの重なりを画面で確認 |
| dialogキャンセル | Escapeで閉じ、`new-game`へフォーカス復帰 |
| ブラウザ例外とconsole error | 上記の操作でなし |
| アクセシビリティ | DOM/ARIA snapshotと入力処理を確認。実スクリーンリーダーによる操作、適合性監査は未実施 |

実スマホのSafari/Chrome、実GPU/WebGPU、低性能端末の描画速度、長時間対局、密集した終盤、初見の人間の理解度は未検証。
今回の評価から描画負荷やAI棋力の良否は判断していない。
