# Quoridor UI/UX調査と改善判断

調査日: 2026-09-29。対象: M1へのユーザー実操作フィードバック（Beads `quoridor-bh9.6`）。

## 現状の問題

- 盤面と常設操作パネルが分離し、盤面の投影サイズが小さい。狭い画面では操作パネルが下へ流れ、やり直す操作にスクロールが必要になる。
- 通常の駒移動にも同じ場所を2回クリックする必要がある。
- 対戦方式の選択が「次の対局の設定」であることと、実際に開始する操作が離れている。
- 起動時の保存選択で保存を削除すると、`clearSave` は保存情報と表示状態を変更するだけで、新しいSessionを作成しない。画面リロードを要するように見える停止状態になる。
- 以前の自動検証では、要素の存在・表示やfull-page画像は確認していたが、主要操作のviewport内到達性や、実際に投影された盤面の大きさを受入条件にしていなかった。

## 採用する画面と操作

2026-09-29のユーザー画像指示により、以下の「上下HUD」は専用レイアウト行ではなく、viewport全面の3D canvasに重なる**独立した小島**と確定した。[HUDオーバーレイ指示図](../design/quoridor-hud-overlay-reference.png)を空間配置の参照とする。上左の状態、上右の操作、下中央の操作以外の隙間からも同じ3Dシーンが見える。指示図の灰色の盤材や背景グリッドは採用条件ではない。

1. **盤面を画面の主役にする。** 常設サイドバーを撤去し、単一の盤面ステージをviewport内へ収める。実際の盤面投影も拡大し、HUDのための余白をカメラ配置に反映する。
2. **HUDは少量にする。** 上部に手番・対戦方式・残り壁数、下部に移動／壁・壁方向・待った。やり直し、新しい対局、設定への入口もスクロールせず届く。HUDの背景は読みやすく、操作域以外は盤面入力を妨げない。ボタンでセルや壁スロットを覆わない。
3. **駒移動を1クリックにする。** 合法な移動先を表示し、クリックで確定。壁はhoverで候補を見せ、クリックで設置。タッチでは候補を選び明示的に確定する方式を許容し、時間依存のダブルタップは要求しない。キーボード選択・Enter確定も維持する。
4. **対局準備を1か所にまとめる。** 「新しい対局」で二人対戦／AI対戦、先後、AI強さを選び、「この設定で開始」で新しい盤面へ切り替える。選択だけで現対局を途中変更せず、キャンセルで現対局を維持する。開始後はHUDに実際の対戦方式を表示する。
5. **やり直しは今の対局条件で開始する。** リロード不要。新しい対局の未適用設定と混同しない。AI思考中・勝敗確定後にも使える。進行中の確認を設けるなら1回の短い確認に限る。
6. **保存復帰に必ず出口を作る。** 起動時には「続きから」と、設定を選んで「保存を破棄して開始」を提示する。後者は削除だけで終わらず、選んだ方式の新しい対局を作成する。壊れた保存でも開始可能にする。対局中の保存削除はその場の盤面を止めず、保存と対局リセットの違いを明示する。
7. **設定と詳細は必要時に開く。** カメラ、保存管理、動きを減らす設定や操作説明は開閉パネルにまとめる。モーダル表示中のクリック・Enterが裏の盤面へ届かず、閉じた後のフォーカスも戻る。

## 検証方針

- 同じviewport・初期カメラで改善前後のスクリーンショットと盤面投影寸法を比較する。canvas寸法だけを盤面拡大の根拠にしない。
- 1280×720、1440×900、1920×1080、390×844で、盤面全体と主要操作が収まり、ページスクロール不要で到達できることを確認する。スクリーンショットはviewport画像も残す。
- ユーザー報告の「二人対戦途中→AI対戦開始」「保存あり再起動→破棄してAI対戦開始」を画面操作で再現し、追加リロードなしで着手可能になることを回帰検証する。
- AI思考・アニメーション中のやり直しやモード変更で、旧対局の結果・保存が混入しない。既存の合法手判定、Undo、保存検証・障害回復を維持する。
- 操作性の最終判断には再びユーザーの実操作を用いる。自動テスト合格を人間の操作感の合格と同一視しない。
