# Sidekickの選択

タスクごとに、環境で許可・利用可能と確認した少数のプロファイルから選ぶ。既定は `standard`。`light` または `deep` を選ぶ理由は短く残す。

| Profile | 目安 |
|---|---|
| `light` | 既存パターンに沿う定型変更で、リスクが低く検証が明確 |
| `standard` | 境界は確定し、内部の実装判断が必要な通常の作業 |
| `deep` | 複雑な状態遷移、強い結合、難しい原因追跡や境界条件 |

行数、ファイル数、経過時間だけでは決めない。どのプロファイルでもSidekickは根拠付きで矛盾を報告できる。軽量プロファイルには既存パターンと確認箇所を明確に渡し、深いプロファイルには探索と局所設計の裁量を残す。

具体的なモデルIDと推論エフォートはSkill外の[このプロジェクトの設定](../../../lead-sidekick/profiles.toml)から解決する。[設定例](../assets/profiles.example.toml)は他の環境向けの雛形であり、実行設定ではない。このプロジェクトではユーザー指定により `light = GPT-6 Luna / xhigh`、`standard = GPT-6 Sol / high`、`deep = GPT-6 Sol / xhigh` を許可する。使用時にもホストの `model/list` 等でIDと対応エフォートを確認する。カタログ掲載だけを利用許可とみなさず、表示名からIDを推測しない。必要なプロファイルが未設定・無効なら勝手に別モデルや課金方式へ切り替えない。他の任意プロファイルだけが無効でも全体を止める必要はない。

関連する修正は互換性のある同じSidekick文脈を再利用する。無関係な仕事や権限境界が異なる仕事を混ぜない。途中のモデル変更は例外とし、まず通常の修正、契約修正、Lead直接対応と比較する。変更時は確定事項、未検証仮説、現差分、失敗した検証を渡し、誤った前提を再点検する。
