# SIGMA-KERNEL-OWNERSHIP (.54)

This is a new single-job ownership experiment. Old .49/.51 failure and g287>91 remain immutable no-go; current parent deadline version2 is recorded separately. No model/kernel/rules/PUCT/clock/watchdog/final-stamp changes, no qualification/actual games/holdout.

runner.py is a fresh, single-thread Python process. Before creating its sole jobroot it proves no existing children, records boot/PID/starttick, checks PR_SET_CHILD_SUBREAPER return0 and PR_GET value1, and installs an audit guard rejecting any additional launcher subprocess/fork/posix_spawn. The only explicit child is the root command. Under that restricted trusted-launcher topology, a new kernel direct child is recorded as `kernel_adopted_direct_child`, independent of polling its departed ancestors, names, UID or PGID. This is a conditional process-ownership inference, not a proof about arbitrary host processes or untrusted code/ctypes/ptrace/namespace changes. All owned identity signals are preceded by current starttick checks. waitid(WNOWAIT) and waitpid target only the caller's same-identity direct children; root exit is handled separately by Popen. The monitor observes20ms and does not establish instant peak or all-host exclusivity.

The existing Node provenance ledger remains available. ACK now carries validated launcher/root/boot scope and kernel-owned identities; Node imports those identities, checks the receipt before signals/success, and preserves absence1000ms/drain100ms. A fake registration cannot confer kernel ownership on a live foreign process; a second launcher spawn invalidates the boundary and prohibits fresh. Childless/single-root assumptions must stay true. No known PID can be used after reuse; unknown children outside the dedicated boundary are excluded. The first failed dummy callback and its separate recovery are retained; recovery is not the original controlled stop success.

It keeps an external sibling alive through the tested cleanup, then its dedicated owner stops/waits it. The job doubleforks with immediate parent exits and setsid, ignores TERM, then the kernel adoption/wait path reaches PID0. Separate policy and extra-spawn diagnostics retain fake/reused/boundary-invalid cases. All outputs have distinct names.
